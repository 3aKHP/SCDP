# 执行 Agent 接手与推进方式

状态：供后续一期执行使用。本文件不表示工程已开始或远端操作已授权。

## 阅读与第一个工作单元

按 [01 接手指南](01-agent-start.md)读取共同规则、状态、研究和设计，再读 [04 一期目标](04-phase-one-delivery.md)、[05 工程任务](05-engineering-work.md)、[06 数据任务](06-data-work.md)、[07 验收](07-acceptance.md)、[08 上线](08-launch-operations.md)和[10 MCP-KB 接入](10-mcp-kb-delivery.md)。

检查实际代码与状态，找到首个未完成任务，不因交接重新下载数据或重建已验证产物。本机资料定位从 local_dev/README.md 读取；详细执行拆解放 local_dev/plans/。

从 E0 开始，首个工作单元交付正式契约草案、合成样例、工程与 CLI 入口、来源许可方案及离线 discover → fetch → decode 小闭环。用当前消费者契约验证交换边界，再逐步实现 E1。不得只搭空目录就将 P0 标记完成。

表中的工作重叠不要求使用多个 Agent。根据当前授权和工具条件执行，跨仓库改动先读目标约定。

## 每个任务的操作闭环

1. 确认输入身份、依赖门禁和当前用户授权。
2. 在本地计划中列出本次变更、预期产物及适当验证。
3. 实现并验证，保存真实命令与结果。故障先保留证据再修复，不重置已有统计掩盖失败。
4. 对照 G0–G10 更新已完成项。文档中的命令、字段和能力声明同步到真实实现。
5. 更新 STATUS 的实际进度和下一步；跨文档概念修改同步术语表，重要决定记录 ADR。
6. 继续后续已授权任务。只对确实缺少的信息或外部权限提出集中问题，同时推进不依赖该信息的工作。

实现、数据验收、发布、MCP-KB 正式消费验收和观察分别记录。未完成任务必须指出下一操作与阻塞条件，不能用“已准备上线”替代正式上线。

## 上线前集中核对

执行早期即可盘点 [08 目标参数](08-launch-operations.md)，但不要在尚无产物时发起宽泛的发布审批。最终外部执行前提供具体候选、目标、摘要、大小、测试结论和回退入口；已明确授权的动作直接按范围执行。

当前用户接受一期文本下载的成本量级。依照范围选择器和有界预算运行，不因正常的文本全量采集逐文件询问；也不将此解释为媒体全量下载授权。Commit、Push、跨仓库写入与生产动作分别核对会话授权。
