## 必须覆盖的故障场景

| 类别 | 场景 | 预期行为 |
|---|---|---|
| 清单 | 304、单分片变化、相同版本内容变化、缺片、错版缓存 | 正确短路或更新；异常阻止候选激活 |
| 网络 | 429、5xx、超时、断连、200 维护页、截断、错误 Content-Type | 有界恢复或隔离；保存原因；不推进 published |
| 容量 | 超大响应、并发预算争用、预算耗尽、磁盘不足 | 流式停止、保留检查点；不能标记完整可用 |
| 剧情 | 重复 id、重复句、空分支、循环、动态条件、跨文件跳转 | 保真且可定位；未知语义如实报告 |
| 译文 | 空译、歧义、原文修订、仅译文更新、同编号多文件 | 独立状态、可追溯对齐、正确增量 |
| 媒体契约 | 多页 atlas、伪装扩展名、可选派生物、必需依赖缺失 | 合成样例验证状态和依赖；不需真实媒体全量下载 |
| 包与发布 | 越界路径、解压超限、摘要错、旧 schema、错误基线、部分上传 | 拒绝损坏包，保留有效版本，重跑幂等 |
| 消费 | 导入中断、索引错配、角色未知、激活失败 | 候选不污染活动数据；提供恢复入口 |

## 最终 MCP-KB 消费验收

执行顺序和已核对的 CLI 入口见 [MCP-KB 接入规程](10-mcp-kb-delivery.md)。以下是 G10 的必需消费结果：

1. 以固定来源范围建立“剧本 → 文档 → 安装文件 → 索引记录”的全量对账，正文帧与文档映射无遗漏。不得使用剧情长度、译文缺失、角色未知、失败路线或热度作为 KB 丢弃条件。
2. collection 在实际服务端可列出、浏览目录、查询大纲。全部文档可经读取接口访问；对存在分页或输出上限的文件分段读取并与源文档核验，不把截断输出当作全文。
3. 使用 `kb_search` 在指定 collection 内查询，使用 `kb_read_chunk` 和 `kb_cat` 读回命中上下文；命中的路径、行号与正文相符。另以 `kb_grep` 验证词法查找与原文读取兜底。
4. 代表样本覆盖每个剧情类别及新旧卡、活动、特殊剧情、失败路线、选择分支、缺译、重复句和未知归属；检查日文与已有中文，检索命中必须来自本 collection。
5. 包清单与服务端安装文件摘要一致，索引不存在无解释的漏文档或旧版本残留。空文本与仅目录说明单独统计，不混入正文分母。
6. 同包重复安装、原文修订、译文单独更新和回退均可验证；其他 collection 与可见性不受影响。正式可见性按目标策略设置，使用对应访问角色验证。

“完整文本”指已声明来源范围内全部可读正文与分支均可消费。完整历史的未恢复清单单列，不能据当前清单验收宣称已证明所有历史内容齐全。

## 公开面检查

按照 AGENTS.md 检查所有准备分发的源码、文档、示例、包元数据、collection.yaml、导入清单、日志、CI 产物和发布说明。公开证据只包含组件名称、通用参数、稳定数据身份和脱敏结果。私有源码映射、主机、域名、IP、账号及本机路径均留在忽略目录。

扫描规则从本地私有映射构建，检查已知标识及 URL、绝对路径等模式，并人工复核 provenance、异常栈和命令回执。检查报告不得在公开日志中重新打印命中的敏感值。源码脱敏通过不能替代生成包的独立检查。

## 真实数据与 CI 的边界

CI 使用合成夹具和本地模拟服务，覆盖逻辑与恢复。真实源验收独立执行并记录输入快照。固定研究样本只作为本地证据，不能直接进入公开测试夹具。

不以逐条联网 HEAD 作为几十万资源的验收方式；目录能力按全量清单验证，文本能力按实际获取与解析验证。媒体内容能力没有真实验证前不声明。

## 验收记录格式

E0 固化机器可读运行报告。至少包括 runId、代码提交与工作区差异摘要、工具与配置身份、来源快照、scope、开始结束时间、测试或检查命令、结果、产物摘要、错误、预算使用与恢复位置。公开记录省略凭证和私人路径，完整回执放本地工作区。

每个门禁状态使用 pending、running、passed、failed 或 blocked，并链接真实证据。blocked 写明具体缺少的输入或外部条件，同时列出仍可推进的任务。修复后生成新运行记录，保留旧失败身份。

最终验收报告分别列出：代码实现、当前清单覆盖、历史审计范围、文档包构建、源包发布、MCP-KB 正式消费验收和运维观察。idolum 的兼容准备与后续接入状态单列，未生产激活不阻塞一期完成。
