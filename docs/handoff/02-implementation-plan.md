## 第一个可交付结果

正式契约与工程入口，加一个可离线重复的 discovery → fetch → decode 小闭环。合成输入覆盖文本、分支、失败路线与通用媒体依赖，再用已有原件和有限真实样本复核。随后推进可恢复的全量文本基线。

## 一期边界

P0–P6 以 MCP-KB 完整文本 collection 的真实消费为最终门槛。idolum 保留契约与政策样例，其生产导入和模型服务接入另行实施，不阻塞一期交付。

通用资产契约、全类型目录和文本中的媒体引用在一期完成。P7 建议先实现一个角色的衣装：索引、resolver、骨架、atlas、多页纹理、校验、兼容投影、缩略图及消费者交付。其他图片、声音和视频逐类接入并独立预算。

## 每阶段收尾

更新 STATUS、对应设计事实和未决事项；记录真实命令、输入身份、产物摘要、验收结果与下一步。状态区分本地实现、数据基线、源包发布、MCP-KB 激活和上线观察。Commit、Push 及远端操作遵循共同规则与当前会话授权。
