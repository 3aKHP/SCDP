# 未决事项与实现前验证

以下问题需要代码、样本或产品策略作出具体结论。既定范围内的可逆工程选择可由接手 Agent 自主完成并记录。

| 项目 | 已知情况 | 接手动作 |
|---|---|---|
| 官方主数据 | 资源清单只有路径与版本 | 调研匿名语义来源；需要账号时先完成独立适配设计与本地可验收结果 |
| say Halo | 有共享引导样本 | 用游戏目录、明确来源和代表性剧情核对全部路线身份，保留未知归属 |
| ?v= 语义 | 路径和版本参数可访问 | 实测是否固定旧内容、缓存与源更新行为，建立快照一致性策略 |
| 未升版本修订 | 目前没有长期观察 | 建立同号漂移检测、滚动内容复核和事件报告 |
| 完整历史 | 当前清单覆盖所有已见汉化编号 | 对官方清单以外的历史来源做独立种子审计，统计历史范围 |
| 控制图格式 | 样本有字符串 select、nextLabel、label | 全量扫描控制键，覆盖动态条件、嵌套／循环和跨文件关系 |
| 媒体定位 | 有逻辑清单与现有 idolum 解析参考 | 各类验证实体 hash、真实后缀和缓存语义 |
| 媒体编码 | 剧情 JSON 解码已抽样 | 音频、视频、纹理、Spine 和效果逐类验证原始与解码 representation |
| 译文来源 | 人工库更新稀疏 | 固定来源 SHA，支持通用回退和缺译；AI 译为独立可选层 |
| idolum 记忆政策 | 现有筛选失败路线且丢弃选择 | 首个适配器核对既有产品行为；分支信息参与检索上下文 |
| 角色映射 | 游戏 ID 与应用角色配置分开 | 保留稳定来源角色身份，映射与未识别角色有报告 |
| 发布排序 | 官方有多个版本计数 | 固化 snapshotId、发布序号、revision 和基线血缘 |
| 分发格式 | JSON／JSONL 可跨语言读取 | 评估归档、可选 SQLite、完整包与 delta 的恢复成本 |
| 首拉成本 | 候选约 1.1 万请求 | 用小规模实际运行估算流量、耗时、断点与全量窗口 |
| 调度位置 | 约 10 分钟目标 | 根据实际主机与权限选常驻调度、构建执行器和失败观察方式 |
| 数据可见性 | 当前仅本地研究 | 明确代码许可、游戏数据使用与分发策略，记录首次发布目标 |

## 容易混淆的口径

- 候选路径、可读剧情、完整章节和独有故事分别统计。
- 翻译非空比例与剧情范围覆盖分别统计。
- 当前清单可发现、实际下载成功和历史可恢复分别统计。
- 首期声明全部类型索引，媒体内容能力通过独立阶段验证。
- 原始素材、解码字节、转码产物、缩略图和消费者布局具有各自来源身份。
- 同名资料目录、源版本和消费者已激活版本分别记录。

## 第一阶段需要明确的选择

实现语言、依赖管理、schema 版本、资产 ID 规范、对象存储布局、发布排序、测试夹具政策和首个许可方案。选择理由写入相应设计或决策文档，避免后续实现沿用临时研究脚本的隐含假设。

## 一期处理时点

| 问题组 | 负责任务与最晚时点 | 未完成时的处理 |
|---|---|---|
| 运行时、schema、身份、许可和包布局 | E0，进入全量采集前 | 先完成合成闭环，不将研究脚本当正式实现 |
| 版本参数、同号漂移和源一致性 | E1、D1–D2，冻结首个候选前 | 明确观察窗口保证，隔离混合结果 |
| 未知控制与正文保真 | E2、D3，G4 前 | 保存全部原件，修复影响必需能力的解析缺口 |
| 语义缺口、译文及历史范围 | D3–D4，G5 前 | 分字段报告 unresolved、缺译与历史差集，不丢正文 |
| collection 格式、索引限制与全文读取 | E3，G7 前 | 对照实际组件实现调整布局或形成补丁 |
| 发布载体、可见性、运行目标与执行授权 | E4 盘点、E5 执行前落实 | 先完成本地产物、staging 和具体发布计划 |
| 私有映射与公开面 | 每次分发前，G6/G10 必查 | 具体值留忽略目录，重新生成脱敏包和报告 |
| idolum 真实导入与媒体内容 | 后续独立接入任务 | 保留一期通用契约与兼容样例，不阻塞 MCP-KB 验收 |

执行任务与验收 ID 见[工程任务](05-engineering-work.md)、[数据任务](06-data-work.md)和[验收矩阵](07-acceptance.md)。文本采集成本范围已明确，按[一期预算](04-phase-one-delivery.md)实施；候选数量仍以运行时清单为准。
