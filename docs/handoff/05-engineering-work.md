# 工程与消费者任务

状态：一期工程任务定义，实际进度见 [STATUS](../../STATUS.md)。阶段编号沿用 [P0–P7](02-implementation-plan.md)，以下任务 ID 用于执行记录和验收关联。每项完成时保存输入身份、输出路径、真实命令、退出结果与未决事项。

## E0 — 工程入口与正式契约（P0）

输入：五篇[设计建议](../design/README.md)、研究摘要、消费者自身当前 contracts 和仓库约定。

执行顺序：

1. 只读核对 SCDP 与辅助仓库状态，记录消费者实际代码基点和已有工作区修改；通过其 README、AGENTS 与领域文档确认导入边界。
2. 优先评估 Python 作为首期生产实现，原因是已有研究工具与 idolum 当前实现便于验证；外部交换使用 JSON/JSONL。将运行时版本、依赖管理、锁文件和目录结构写成 ADR，选择时验证实际环境支持。不得将建议语言当作现成决定。
3. 固化 Snapshot、Asset、AssetVersion、Representation、Story、Translation、Entity、Relation schema。明确 required、nullable、未知枚举、扩展字段、来源命名空间、帧发生位置和兼容升级规则。
4. 定义 source observation、不可变内容对象、构建快照和公开版本的身份关系。固定排序编码、摘要范围、时间字段、发布序号、revision、完整包及基线规则。
5. 定义可读文档布局与稳定文档 ID，原始字节、解码字节、结构化记录和文档互相可追溯。首版建议完整压缩包，delta 可在证明成本必要后增加；首期必须支持源增量处理和消费者幂等更新。
6. 用纯合成样例覆盖文本分支、失败路线、图片、Spine 多页依赖、音频、视频和派生物。实现 Python、Go 两个最小读取验证入口，比较同一包的身份、摘要及依赖解析。
7. 创建 CLI、日志、配置、预算账本和失败退出码约定。配置包含来源、工作目录、选择器、缓存、并发、流量上限、超时、重试、目标载体；凭证通过运行环境注入。
8. 首次复用参考代码前固定源文件及许可证，记录复用范围和许可选择。保留来源声明，测试不复制游戏正文。

推荐职责目录为 src/、schemas/、tests/、docs/，实际布局在 E0 确定。CLI 至少具备 discover、fetch、decode、build、validate、package、publish-plan、publish、status、resume 的职责；这些名称目前是接口提案，不是可执行命令。完成 E0 时必须用真实命令替换运维示例，并通过 `--help` 与合成闭环校验。

退出条件：干净环境能安装、运行合成闭环和双语言契约检查；正式 schema、示例、许可与 CLI 文档均存在。完整媒体内容获取不是此门禁。

## E1 — 可靠发现、获取与恢复（P1–P2）

依赖 E0。实现官方主清单与分片读取、条件请求、内容指纹和缓存来源核验。相同版本号不等于相同内容；损坏或错版缓存不能直接复用。

实现按类别的 resolver 与 decode，路径拒绝绝对路径、越界、归一化冲突；HTTP 错误、维护页、空内容、截断、错误 MIME、未知编码分别分类。摘要明确是否已发生 HTTP 解压。所有下载先写临时对象，校验后原子落盘。

实现共享字节预算、单响应上限、受控并发、速率限制、超时、重试退避、负缓存过期、进程锁和持久检查点。重启继续原作业账本；同一对象命中缓存时校验身份与摘要。请求中断、磁盘不足或预算触发不能留下被标为 available 的不完整对象。

先用本地合成 HTTP 服务验证错误路径，再执行[真实数据任务](06-data-work.md)。退出条件为验收 G1–G3 通过，能够从断点恢复并离线重建索引。

## E2 — 剧情、译文与阅读包（P3–P4）

依赖 E1；元数据来源核对可在获取实现期间推进。

先保留全部帧，再提取正文、说话人、旁白、选择、标签、跳转及媒体引用。帧身份使用原始序号与发生位置，不依赖游戏 id 唯一。控制图支持未知节点和未解析边，保存原始控制字段；未知分支不得直接拼成确定的单线经历。

元数据和译文按独立来源适配器处理。实体关系记录证据与确定性；人工译、通用回退、缺译和歧义分别表示。对齐以原文及上下文为依据，重复句不得仅按文本相同合并。原文修订使旧对齐重新验证。

生成阅读包时按剧本及分支组织章节，展示选项与跳转目标，保留原文格式信息及定位。文档中的稳定媒体引用只链接目录记录，不能触发下载。每篇含来源与译文状态，总目录包含类别和未解析归属入口，孤立或未知角色剧情仍可发现。

退出条件为 G4–G6 通过；从原件离线重建得出相同语义记录与文档内容。构建时间等易变字段单独定义，不以整个归档字节一致替代语义验证。

## E3 — MCP-KB 接入与 idolum 兼容准备（P5）

输入为已通过 G4–G6 的候选包。先读目标仓库自己的约定并核对本次跨仓库授权；授权未覆盖实际改动时先在 SCDP 完成适配产物、契约测试和可审阅补丁。

| 消费者 | 实现工作 | 必须验证 |
|---|---|---|
| MCP-KB | 生成符合当前协议的 collection、docs、references 与导入清单；按目标流程验证、打包、安装、建索引 | 全文与分支可检索，文档 ID 稳定，同包重装幂等，新增、修订、退役有明确处理 |
| idolum | 一期提供导入边界设计、角色映射和政策合成样例；实际导入器按后续授权实施 | 契约可表达双语、分支及未知角色，消费政策与源数据独立；生产迁移不作为一期门禁 |

后续实施 idolum 导入器时，切块与向量缓存按实际检索输入及模型身份失效；模型维度变化有显式处理。先使用隔离测试库和合成嵌入服务验证流程，再在部署配置允许的范围验证真实模型。不能把模拟结果标为生产向量化通过。

MCP-KB 必须先在 staging 导入和查询，验证失败保留原有数据。idolum 实际接入时沿用相同候选验证原则。生产数据库中的用户资料不作为研究输入，导入只走契约允许的剧情更新边界。消费者间不要求分布式原子切换，但必须记录各自激活快照，报告短暂版本差异。

退出条件为 G7 通过，MCP-KB 具有可执行的安装、升级、回退说明，idolum 兼容设计与合成样例通过契约检查。MCP-KB 正式激活在 E5 完成。

## E4 — 打包、发布与运维实现（P6）

固定文件清单、大小、摘要、scope、capabilities、工具身份和来源血缘；验证归档路径安全及解压容量限制。发布器先生成计划，再创建候选、上传、读回核验，最后切换可发现版本。相同公开版本不能覆盖不同内容。

实现调度锁、无变化短路、变化分片处理、独立译文更新、同号漂移事件和有预算的滚动复核。状态报告区分发现、获取、验证、发布与消费者激活。部署模板按选定环境提供启动、停止、日志、恢复和凭证键名说明。

退出条件为 G8–G9 通过，准备好具体目标的发布候选、费用与存储估算、回退演练和实际命令。远端执行按[上线步骤](08-launch-operations.md)进行。

## E5 — 正式上线与交接

依赖 E0–E4 与全部基线数据门禁。完成正式发布、MCP-KB 完整 collection 消费验收及上线观察，达到 G10。交付后更新 STATUS、工程入口、设计事实和未决事项；接受的架构决策与实现状态分别维护。
