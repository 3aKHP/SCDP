# 上线、更新与恢复

状态：上线与观察要求。实际命令见[运行指南](../../dev/running.md)和[运维指南](../../dev/operations.md)，可复用配置见[部署模板](../../../deploy/README.md)，执行结果见 [STATUS](../../../STATUS.md)。

## 目标参数

执行 Agent 先从已有授权和目标仓库配置确认下表。只收集缺少的信息，凭证仅检查键名或脱敏状态。参数未确定时可继续本地实现、全量文本构建、staging 验证和发布计划。

| 参数 | 需要确定的内容 | 未确定时可推进的工作 |
|---|---|---|
| 代码托管 | 仓库归属、远端、代码许可、提交与推送授权 | 本地实现、差异检查、候选提交说明 |
| 数据分发 | 目标存储、地址、可见性、访问方式、数据使用与分发政策 | 本地不可变包、摘要、发布计划；不默认公开 |
| 执行环境 | 主机或运行器、运行身份、持久卷、网络路径、调度方式 | 部署模板、隔离演练、请求与存储估算 |
| 消费目标 | MCP-KB 安装目标、collection 导入边界和备份入口；idolum 实例在后续接入时确定 | 适配产物、测试库和 staging 导入 |
| 后续模型服务 | 实施 idolum 接入时核对模型身份、维度、调用预算与凭证键名 | 一期保留合成兼容验证，不阻塞 MCP-KB 上线 |
| 运维责任 | 日志位置、运行报告、维护者、已授权通知渠道 | 本地报告和错误分类；不擅自外发消息 |

建议一期采用一个具有持久状态的采集／构建执行环境，加不可变文件分发载体。按部署条件选择常驻调度或已有运行器，不要求为一期引入独立 Web 服务或复杂集群。实际选择、保留策略和存储成本由 E4 记录。

## 授权与执行边界

本计划制定请求授权编写计划，不能当作已授权执行远端写入、生产部署或跨仓库修改。后续收到执行任务时，合并已有明确授权；对已授权行动持续推进，无需重复确认。

依据 [AGENTS.md](../../../AGENTS.md)，Commit 和 Push 分别需要相应明确指令；远端写入和生产操作按明确执行授权开展。遇到缺少授权的最终动作时，先完成可逆实现和验证，提供具体目标、包大小、摘要、变更范围、费用及回退方法，再集中说明剩余动作。不能仅因目标尚未确定就停下整个工程。

## 首次上线顺序

1. **冻结候选。** G0–G9 通过，固定代码及工作区身份、来源快照、schema、消费者政策、文档包和机器包摘要。记录已知元数据缺口和历史范围。
2. **准备目标。** 按实际授权配置仓库、分发载体、运行身份、持久目录与凭证引用。校验可用空间至少覆盖现有保留版本、候选、临时展开及下一次构建；首次基于测量写出具体容量。
3. **安装运行环境。** 锁定依赖，使用最小必要权限；验证读源、写候选、读回包和报告能力。定时器先不启动自动激活。
4. **上传候选。** 创建 draft 或等效未激活版本，上传文本产物、清单、摘要与必要说明。失败从已验证对象继续，不覆盖既有公开身份。
5. **从消费端验证。** 使用实际消费身份下载包并核对大小和 SHA-256，执行 schema、归档安全、范围与依赖校验。上传端成功不能替代消费端可达性。
6. **正式分发。** 校验通过后将候选设为可发现版本，保存正式地址、版本和发布时间。首次无前代时明确记录恢复策略为停用首版或重建候选。
7. **激活 MCP-KB。** 安装候选 collection，构建索引并执行代表性查询，完成目标系统允许的切换。保留已有有效 collection 与索引恢复入口。
8. **验收完整消费。** 按 G10 逐条对账 collection 与索引覆盖，验证检索和全文读取；保存脱敏报告。idolum 的真实部署另立后续任务。
9. **启用调度。** 开启单实例锁和运行报告。建议目标为约 10 分钟条件检查，实际周期与延迟按环境验证，不能把计划周期当作端到端更新保证。
10. **完成观察。** 按下节保存证据后更新 G10、STATUS 与维护指南。

MCP-KB 激活失败时保留上一代并恢复候选，成功后补齐一期验收。idolum 的后续接入独立记录状态。

## 上线观察

建议首次上线观察 24 小时；完成验收至少需要实际定时执行 3 次，确认进程重启后检查点、账本和锁恢复正常。记录发现延迟、构建耗时、传输字节、失败次数、磁盘占用和 MCP-KB 活动版本。

期间至少验证一次真实无变化路径。自然更新未出现时，用隔离命名空间和合成变更演练发现到发布、再到 MCP-KB 候选导入的完整路径，不能向正式资料伪造游戏更新。演练证据与真实更新记录分别标注。

至少完成一次错误包拒绝、一次中断恢复和一次旧有效版本恢复。首次上线无前代正式版本时，在隔离消费环境构造两个有效合成版本演练回退，并验证生产停用入口。

## 稳态更新

每轮条件读取主清单；无变化时记录心跳，变化时获取所需分片与文本差集。翻译和元数据分别检测版本，单独触发派生重建。滚动内容复核在独立预算内进行，追踪未升版本修订。

候选通过相同门禁后发布，消费者先验证和导入再激活。清单移出标记 historical，不自动删除原始归档。发布包和共享对象保留策略必须保护活动版本、上一有效版本及其完整依赖闭包。空间回收先生成待删清单，按授权执行，不通过清理未核对对象解决磁盘告警。

## 故障处置

| 现象 | 立即动作 | 恢复及验证 |
|---|---|---|
| 超时、429 或服务维护 | 保留检查点，停止超预算重试 | 按退避策略续跑，核对成功对象复用和账本 |
| 同号漂移或前后源不一致 | 保留旧发布，隔离候选并记录事件 | 固定新观察，重新处理变化对象后完整验收 |
| 未知控制或对齐异常 | 保留原件，不宣称受影响能力通过 | 合成复现、修解析器、离线重建及回归 |
| 上传部分失败 | 保持候选未激活 | 比对远端对象摘要，补缺后消费端重新核验 |
| 消费导入或索引失败 | 该消费者继续使用上一代 | 修复后重导候选，核对幂等与代表性查询 |
| 发布后发现正文错误 | 停止推进错误版本，切回已验证消费版本 | 生成向前 revision，保留原发布身份和事故记录 |
| 磁盘不足或凭证失效 | 停止新写入或发布，保留有效对象 | 修复容量或凭证配置，恢复检查点并核对摘要 |

消费者回退与公开发布修订分开处理：允许消费者临时激活旧有效版本，但不能把公开版本号倒退或用不同内容覆盖旧包。

## 交接材料

上线后提供真实安装与运行命令、配置键说明、数据目录职责、定时器状态、包与消费者版本查询、恢复操作、容量账本和已知缺口。执行回执保存于本地工作区；共享文档只包含可分发说明和脱敏证据。
