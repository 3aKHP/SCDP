# 首次全量文本与数据验收任务

状态：一期数据任务定义，实际进度见 [STATUS](../../../STATUS.md)。真实下载遵循[一期范围与预算](04-phase-one-delivery.md)。本文件给出数据处理顺序，字段定义以正式 schema 为准。

## D0 — 固定来源与调查目录

1. 核验本地研究输入摘要，将已有索引、分片和样本登记为历史观察，避免误作当前源版本。
2. 审阅离线资源地图的目录组和未知模板，结合客户端资源引用建立类型分类与 resolver 证据。全部路径均进入目录，无法分类的保持 unknown。
3. 固定汉化来源提交，列出其许可、文件范围、重复剧本编号和缺失编号。缓存可复用时先验证摘要；获取更新时避免无需要的完整 Git 历史。
4. 核对语义来源的字段、身份与更新时间，制作字段来源表：标题、角色、卡片、衣装、活动、顺序、解锁条件。注明明确来源、编号推断、冲突和未知。

产物：来源注册表、分类规则、字段来源表、历史种子表。无需把几十万条目录逐条提交给模型；脚本全量统计，人工审阅组摘要、异常及代表样本。

## D1 — 当前清单与首轮采样

依赖 E1 的合成错误与预算测试通过。获取主清单及需要的分片，固定完整观察身份，重新计算文本候选和媒体目录。必要时与研究快照比较新增、变更、移出和类别变化。

覆盖每个剧情候选类别选择少量代表文件，优先命中已有可验证缓存。补充新旧卡、活动、生日／特别剧情、培育、失败路线、选择跳转和 say Halo 代表样本。每个样本写明选取原因，不能将便利样本当作随机总体。

统计各类传输正文、解码大小、耗时、重试和帧数，给出按类别估计的总量及不确定性。预算允许且无错误趋势即可继续全量，无需因每个样本重复请求下载许可。首次抽样的主要用途是验证实现和异常检测，不能替代全量基线。

产物：冻结清单、选择与排除明细、样本报告、剩余请求和流量估算。

## D2 — 可恢复的全量获取

1. 为冻结选择集建立作业，每条记录源路径、源版本、观察身份、尝试状态与对象摘要。
2. 受控获取全部选中剧情，保留原始响应与解码字节。失败响应按保留政策隔离，不能作为剧情发布。
3. 中断后从检查点恢复，只重试缺失、损坏或身份不匹配的对象；负缓存按政策复查。
4. 完成后重新核对主清单和分片。跨更新窗口时保留已有对象，将变化条目重新获取，直到形成可解释的一致候选。
5. 官方版本参数是否固定旧内容仍需验证；未证明时将快照声明为固定观察窗口的归档，不宣称可访问任意旧版上游。目录前后相同也不能证明服务端从无同号修订，按滚动复核记录保证边界。

每条路径必须落入成功、带证据的来源缺失、明确政策排除或未解决失败之一。未解决失败阻止正式激活。已知来源缺失需稳定复查、原因证据与包内范围声明；不能为通过验收临时扩大排除政策。

产物：全量原件、对象目录、检查点、覆盖报告、流量账本和源一致性报告。

## D3 — 全量结构扫描与语义整理

对全部已获取剧情统计帧类型和控制键，列出解析覆盖与未知结构。发现新结构时先保存原件和最小合成复现，再完善解析器并离线重跑。不能只验证已知的 select、label、nextLabel。

逐篇校验可读原文帧与正文发生位置一一对应；选择文本和所有路线保留。图检查包括目标存在、入口、汇合、循环、跨文件及动态条件。涉及未知语义的内容在阅读包中显式展示原始控制证据与未解析状态；若会损害正文保真或必需消费语义，则阻止相应能力发布。

按字段来源表合并实体与关系。say Halo 和近两年特别剧情使用可追溯目录及代表文件核对，未知归属独立列出；不能靠缺少语义元数据把正文从包中剔除。

产物：剧情结构、实体关系、未知控制清单、元数据覆盖和重点类别核验报告。

## D4 — 译文与历史审计

逐文件解析固定译文快照，按稳定 scriptId 与帧上下文对齐。分别报告唯一剧本覆盖、正文非空译文、确定对齐、歧义、失效和缺译；所有比例注明分母。

汉化重复编号、共同说话人、原文重复、空译文和上游修订均需显式处理。仅译文更新可重新构建文档和消费者投影，不要求重下载不变的原文。

将历史种子与当前清单比对。当前清单外但有本地译文或其他来源的文本可以按独立来源归档，不冒充官方原件；来源不足的项目保留待恢复记录。报告历史范围与当前清单覆盖两个结果。

产物：对齐结果、来源血缘、缺译与歧义报告、历史差集。

## D5 — 文档包与真实消费样本

从正式结构生成全部阅读文档、机器记录与目录，运行全包 schema、摘要、路径、正文保真和能力校验。输出压缩前后大小、对象复用量、最大文件和消费者所需磁盘空间；压缩文本包的实际字节数作为下载依据。

真实人工抽检至少覆盖 D1 列出的类别，包含缺译、同句重复和未知归属；记录具体稳定 ID、检查项目与结果，不在公开报告复制剧情正文。全量自动校验与人工抽样分别报告。

将候选包交给 E3 执行 MCP-KB staging 验收。collection 必须保留全部范围内正文与分支，不能套用 idolum 的经历筛选。idolum 的兼容样例独立检查，不缩小 KB 文本范围。

产物：正式候选包、可读目录、全量验收结果、MCP-KB 候选状态及 idolum 兼容检查结果。随后进入[上线步骤](08-launch-operations.md)。
