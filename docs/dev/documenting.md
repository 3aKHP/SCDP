# SCDP 文档规范

本规范供贡献者和 Agent 编写、修改、生成与审查 SCDP 文档。目标是让读者找到事实依据、理解条件并完成相应任务。

适用范围包括根目录协作说明、docs/、配置注释、随包说明、schema 描述和合成示例。

## 文档职责与权威来源

| 位置 | 主要职责 |
|---|---|
| `README.md` | 项目定位、主要范围、接入入口与导航 |
| `STATUS.md` | 当前阶段、已完成能力和下一步交付 |
| `docs/glossary.md` | 概念名称、简短定义和详细规则入口 |
| `docs/research/` | 带观察日期与来源身份的研究结论和可分发摘要 |
| `docs/design/` | 架构、数据、媒体、消费者和发布设计，明确其状态 |
| `docs/handoff/` | 当前维护者接手入口与旧地址迁移说明 |
| `docs/guides/` | 下载、读取、采集、集成与运维操作 |
| `docs/reference/` | CLI、配置与包格式参考 |
| `docs/history/` | 标明日期与状态的历史任务和验收材料 |
| `docs/dev/` | 工程规范与开发维护要求 |
| `docs/dev/adr/` | 重要技术选择的背景、理由、状态和后果 |
| `local_dev/` | 本机计划、草稿、原始样本、执行回执、私有映射与工具 |

同一事实在最贴近读者任务的文档中维护完整说明，其他页面提供摘要与链接。长字段表、默认值、状态定义和验证矩阵保留单一权威入口。

新增页面须在所属目录 README 和 docs/README.md 登记到合适层级。系列页面由系列索引维护，总导航链接系列入口。改名、移动和标题调整同步核对链接与锚点。

面向使用者或运维人员的指南围绕安装、消费、同步、恢复和排障任务组织入口。

## 当前事实、设计与证据

- 当前能力以实现、解析器、schema、公开模板和实际验证为依据。
- 候选设计标明状态；正式字段和命令形成后同步更新设计和使用入口。
- 研究数据写明观察日期、来源提交、样本范围、分母、方法和结果。
- 已完成任务更新 STATUS 和任务状态。执行经过与重复运行的回执保存在本地工作区。
- 外部平台信息给出适用版本、核对日期与直接来源，推断注明依据。
- 原文路径数、可读剧情数、语义映射率、翻译覆盖、资源可用率和消费者激活各自报告。

研究快照保留当时事实。后续验证记录新的观察身份，相关说明链接到对应版本。

## 公开资料与本地工作区

公开文档通过仓库分发内容即可理解。文件链接使用仓库内相对路径，目标须存在且可纳入版本管理。本地工作区可以用普通路径说明用途，公开页面的操作流程具有可重建输入。

本机绝对路径、同级仓库的实际摆放、会话状态、执行计划、原始游戏正文、私人部署资料和凭证进入 local_dev/。公开示例使用可分发路径、占位符和虚构内容。

研究摘要可以保存来源提交、目录统计、内容摘要和无凭证的公开 URL。完整原件与本机索引存放于本地工作区，版本管理中的 provenance 保存足够核对公开摘要的信息。

共享交接文档说明项目范围与可复用步骤。本机交接补充目录位置、原件与执行证据的查找方式。

## 表达与排版

先给出结论、用法或操作入口，再解释必要原因。每段发展一个主要意思，条件与动作按实际顺序衔接。

自然语言说明行为，命令、字段、路径和错误标识帮助定位对象。平行信息用列表，映射用表格，操作顺序用编号。避免用分号或斜杠拼接多个维度的要求。

直接描述目标版本的完整行为。演变和事故经过记录到变更说明、迁移文档或明确的历史材料。保留正确事实与必要条件，局部修改围绕具体问题进行。

限制应解释触发条件、后果与处理动作，并放在影响读者选择的位置。待办集中维护在任务和未决问题中。减少重复总结、泛化风险声明、抽象名词堆积与无证据评价。

文本统一 UTF-8 与 LF。段落和列表项按语义组织，正文保持自然段。中文散文使用全角标点和弯引号；代码、命令与配置使用对应语法的 ASCII 字符。路径、配置键、命令与标识符使用行内代码，多行示例注明语言。

当前正文采用中文，标识符保留原样。新增其他语言版本时，明确权威版本和互链，并在同次变更同步技术事实与结构。

## 操作、配置与示例

操作文档交代输入、工具、权限、执行目录和环境。依次说明操作对象、输出位置、生效方式和成功时可观察的结果。排障按现象、检查方法、处理动作组织。

完整配置、可合入片段和设计伪代码分别标识。片段注明放置位置、占位符和必要上下文。正式命令与字段采用实际名称，尚未实现的接口说明其候选状态。

复制执行的代码块只放可用语法，预期输出和解释另行呈现。涉及真实请求、费用、覆盖或删除时，在相应步骤说明目标与前提，验证使用隔离环境或合成资料。

优先使用项目现有解析器、schema 校验器与 CLI 核对示例。语法通过、离线重放、真实样本、全量采集和生产激活分别记录真实执行结果。

## 术语与决策

跨文档概念由 [术语表](../glossary.md)统一名称，具体约束在对应设计或正式契约中维护。

影响资产身份、版本、持久化、依赖、消费者兼容或发布协议的决定，使用 [ADR](adr/README.md)记录。ADR 状态表达决定的状态，实现进度由任务和 STATUS 跟踪。真实候选方案与代价有来源依据。

## 维护与审查

行为、字段、版本、路径或流程变化时，在同一变更更新拥有该事实的文档、示例与相关入口。生成副本由生成工具维护，并核对源文件与副本的一致性。

交付前检查：

- 目标读者是否能找到入口并完成任务？
- 当前行为、设计、研究快照和执行记录是否各归其位？
- 字段、命令、默认值、权限、状态和生效顺序是否有实际依据？
- 示例、链接、锚点、编码和文件引用是否通过相应检查？
- 修改是否保留了原有正确事实与关键条件？
- 公开说明是否能够从仓库分发内容独立理解？

评审指出具体位置、读者会遇到的问题和修订方式。关键词搜索用于定位候选，结合句子职责和事实证据作出判断。
