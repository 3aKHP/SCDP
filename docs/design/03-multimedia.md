# 多媒体资产与交付

状态：当前仅提供全类型目录、文本媒体引用和合成依赖验证。以下内容下载、转码和交付方案属于后续设计，尚未实现。

## 当前范围与后续需求

idolum 未来将消费非文本多媒体。第一阶段的资源模型、版本包和依赖设计应支持该消费方向。初版扫描全部官方索引，媒体默认仅记录目录与引用；首期下载选择器集中于剧情原文。

后续资产范围包括卡图、头像、背景、Spine、纹理、原作语音、BGM、SE、视频、字体和效果资源。各类别有独立下载选择、预算、解码、校验与交付能力。

## 扩展边界

建议按以下职责设计适配器：

| 职责 | 行为 |
|---|---|
| discover / classify | 将来源条目识别为通用 Asset，保留 unknown |
| resolve | 逻辑路径、实体信息和源版本 → 实际下载定位器 |
| fetch | 获取原始响应与可重试结果 |
| decode | 返回表示形式及处理证据 |
| validate | 类型结构、完整性和资源依赖检查 |
| project | 为消费者生成布局、索引、缩略图或其他派生物 |

接口名称由正式实现确定，职责需保持清晰。多媒体包可按类别、实体或大小分片，消费者通过通用索引选取。

## 逻辑路径与实际路径

官方静态清单中的逻辑路径、实际哈希 URL、实体身份与 SCDP 对象引用分别记录。部分媒体定位还涉及卡片或衣装 hash、后缀、来源域名、资源变体和版本参数。解析规则需要按资源类别实测并固定版本。

研究参考的剧情 JSON 解码函数覆盖范围有限，接入音频、视频、纹理和效果时须检查各自响应和编码。清单只能证明条目被声明，实际可用性由获取与校验结果证明。

## 多文件资源组

Spine 通常包含 skeleton JSON、atlas 与一张或多张纹理。组内依赖应解析实际 atlas 页名，支持多页纹理、别名和缺失状态。观察到过 .png 路径返回 WebP，以及 atlas 引用 date.png 等情形；新来源与新变体需重新验证。

保持原始字节。兼容性 atlas 修补、纹理转码、重命名和缩略图渲染生成独立派生对象，记录输入、工具和处理规则。组的 ready 状态要求所有必需依赖可用；可选缩略图具有独立状态。

## idolum 参考消费布局（2026-11-10 调查）

当前实现读取 source/spine_manifest.json 与 source/assets/spine/idols/<category>/<enzaId>/。常用 category 为 stand、stand_costume；生成 outfits/<idol_id>.json 与 thumbnails/<category>/<enzaId>.png，并将相关文件上传到部署者对象存储。

可先实现兼容投影，让现有 stand outfits／stand upload 读取 SCDP 已校验资源。通用源目录继续保存全部资源种类与源身份；衣装去重、默认衣装选择、缩略图样式由消费者投影处理。

## 引用与运行交付

- 帧与媒体使用稳定 assetId 关联，避免在正文中绑定易变上游 URL。
- 包与对象定位采用可配置 resolver，支持本地缓存、归档成员和对象存储。
- 消费者按需求获取媒体及其依赖闭包，先验证对象，再发布引用清单。
- 已激活快照引用不可变资源版本；修订生成新资源引用，缓存策略与身份一致。
- 通用索引声明 representation 的真实 MIME、大小、摘要和缓存身份。大媒体交付预留流式读取与 Range 能力。
- 资源退役、临时不可用、依赖缺失和缓存未命中分别处理，idolum 能按自身产品规则降级显示。

## 分阶段交付

首期交付全部类别索引、文本帧引用和未解析关系，验证合成的 Spine 依赖组和媒体解析器契约。

后续阶段实现 Spine／纹理／缩略图与 idolum 衣装接入，再逐类扩展卡图、背景和原作音频视频。原作媒体与 idolum 生成的 TTS、用户照片、会话音频和个人记忆具有独立数据生命周期；SCDP 发布原作资产及明确标记的公共派生物。

各类首次全量采集前建立请求量、存储量和传输预算。官方 totalSize 为当前清单声明值，实际可获取与历史累积空间另行统计。
