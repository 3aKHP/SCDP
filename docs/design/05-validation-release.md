# 验证与发布

状态：验证与运维约束，实际门禁结果见 [STATUS](../../STATUS.md)，操作入口见[运维指南](../dev/operations.md)。

## 指标口径

分别报告发现路径、选择路径、成功下载、有效解码、可读剧情、唯一正文、语义映射、译文对齐、媒体组 ready、消费者已激活的数量与范围。每个分母对应当前快照与政策，提供未解析和排除原因。

文件数量或非空译文比例均应保留自己的统计口径。完整历史和当前清单覆盖具有独立报告。

## 采集与恢复

- 条件请求 304、无变化短路、变化分片更新、同版本清单漂移。
- 限速、超时、429、5xx、断连、重试耗尽、中断后继续、重复执行。
- HTTP 200 的 HTML／维护页、空响应、伪 JSON、截断流、解码失败。
- 分片缺失、前后清单不一致、资源 counter 与内容变化关系。
- 明确缺失与暂时异常分别处理；负缓存有重试与过期政策。
- 部分完成的数据保留检查点，正式发布引用符合范围政策的完整集合。

## 结构与翻译

用虚构帧和选择关系覆盖重复 ID、相同日文多次出现、旁白、原始格式、互斥分支、嵌套跳转、空分支、未知控制字段和失败路线。

逐篇验证可读原文的帧定位与输出保真，图边引用存在、入口和可达性明确。循环、动态条件、跨文件跳转等保留证据并给出处理结果。

人工译、通用回退、AI 译、空译、歧义、源文件修订、上游增删和失效译文有独立测试。原文获取和原文发布能够在缺译状态下完成。

## 通用媒体契约

即使首期仅下载文本，也应使用合成媒体组验证通用记录：同路径不同内容、真实 MIME 与扩展名不同、atlas 多页纹理、可选缩略图、必需依赖缺失、媒体引用未解析、资源缓存过期与新版清单切换。

大文件按流式方式验证摘要和大小，分片支持重试。原始资源与修补派生物的摘要、输入和处理版本能够回溯。

## 首次真实验收

全量首次下载以固定官方清单为基准，每个选中条目都有成功或明确异常结果。已知来源缺失需要证据、范围政策和覆盖声明；新出现且无法解释的缺失阻止推进已发布版本。

真实抽样覆盖旧与新卡、活动、生日／特别剧情、培育、失败路线、选择跳转及新版培育归属。抽样结果与全量静态校验分别记录。

## 发布

沿用 AKDP 的 draft-first 和不可变发布思路。完整候选通过源一致性、内容保真、契约、依赖、回归与包摘要校验后公开为目标分发状态。发布器默认生成可审阅计划，实际远端写入由明确执行入口触发。

同一公开身份的内容保持不可变，修复使用向前 revision。正式发布序列保存快照、血缘、包大小与 SHA-256、工具版本、来源快照和验收摘要。公开日志仅保留可公开证据。

Git 仓库存代码、schema、合成夹具和小型说明。数据包通过 Release／对象存储等载体分发，具体可见性和存储政策在首次发布前确定。

## 消费激活

消费者核验支持的 schema、capabilities、包摘要和基线依赖。在候选状态完成导入与代表性查询后切换，错误保留上一代有效数据。MCP-KB 和 idolum 分别报告“源包已构建”“适配产物已验证”“消费者已激活”。

## 时效与成本

建议采用轻量常驻调度器执行约 10 分钟条件检查，构建可使用 GitHub Actions。记录官方变化观察、任务排队、构建完成、包发布、消费者激活的各自时间。GitHub schedule 的时延单独观测。

每阶段记录请求数、下载字节、耗时、重试、增量与累计空间；按来源和资产类别控制预算。LLM 摘要、AI 翻译和向量化属于独立可选构建或消费阶段。
