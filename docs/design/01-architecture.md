# 系统架构

状态：架构职责与约束。当前模块见[运行指南](../guides/collect.md)，字段见[正式契约](../../schemas/README.md)，验收进度见 [STATUS](../../STATUS.md)。

## 职责

SCDP 为 enza 页游生产版本化事实数据和通用资产目录。首期下载剧情原文，整理关联元数据与已有译文；未来扩展多媒体下载和交付。MCP-KB、idolum 和未来消费者复用相同资产身份。

~~~mermaid
flowchart LR
    A[官方主清单与分片] --> B[资源发现与快照]
    B --> C[通用资源目录]
    C --> D[按资产类别获取与解码]
    D --> E[不可变对象与历史记录]
    E --> F[剧情解析与来源对齐]
    G[语义元数据与译文] --> F
    F --> H[校验与版本发布]
    E --> H
    H --> I[MCP-KB 适配]
    H --> J[idolum 适配]
~~~

## 分层

| 层 | 输入与输出 | 责任 |
|---|---|---|
| discovery | 官方清单 → 全类型资源目录 | 分片版本、路径、首次与最近观察、清单身份 |
| fetch | 资源记录 → 原始字节与响应证据 | 限速、重试、断点、来源定位、维护页识别 |
| decode | 原始字节 → 表示形式 | 按资源类型选择解码器，保留原件与工具身份 |
| catalog | 资源及语义来源 → 实体与关系 | 剧本、角色、卡片、衣装、媒体、未知关联 |
| story | 原始帧 → 正文、控制关系与引用 | 帧序、旁白、选项、标签、跳转、互斥路径 |
| translation | 译文快照＋原文 → 行级对齐 | 确定匹配、歧义、缺译、源修订失效 |
| package | 已校验快照 → 版本包 | 契约版本、完整性清单、差异、引用与发布身份 |
| adapters | 标准包 → 消费者产物 | KB 阅读文本与隔离安装，idolum 合成兼容预览 |

运行时为 Python 3.12+，CLI 协调采集、构建与发布模块。对外使用 JSON／JSONL 和 Markdown，消费者不依赖 Python 内部对象。当前不调用翻译或摘要模型。

## 原件与派生物

保留服务器返回的完整响应实体字节、解码后的原始 JSON，以及下游结构化表示。定义 HTTP 传输解压是否已发生，并在摘要字段注明 representation；编码流摘要和解码摘要分别计算。规范化文本、格式重排、文本处理记录来源与工具身份；未来纹理转码、atlas 修补和缩略图也需要独立记录输入与规则。

不可变内容对象可按 SHA-256 寻址。稳定逻辑路径与每代内容对象通过资源版本记录关联；同一路径发生改变时保留前代。当前清单观察与历史归档记录分别查询，清单移出不自动删除历史内容。

## 源版本与一致性

官方主清单 version、分片版本、每个资源的版本计数、译文 Git SHA、元数据观察身份分别记录。SCDP 发布具有自己的不可变身份与向前修订号。

构建前固定主清单和分片快照，构建后核对清单身份。跨更新窗口的混合结果保留为暂存证据，重试到一致快照后发布。官方 ?v= 行为尚需专项验证，缓存参数的版本约束能力应有实测依据。

清单相同版本发生内容漂移时记录事件并按来源策略处理。定期滚动复核用于发现未反映在清单版本中的文件修订。所有指纹算法明确规范排序、编码和作用范围。

## 稳态自动化

systemd 模板每 10 分钟触发一次 cycle，条件读取主清单；存在变化时只读取变化分片并计算首期资源差异。翻译或语义元数据独立变化时可触发对应派生产物构建。首次全量获取须持久化检查点。

自动化在明确的契约与分类范围内推进。异常保留上一代可用发布并报告失败类别、重试状态和缺口。原件存储成功后，解析器的更新能够离线重建结构化产物。

## 构建与消费身份

当前版本包为完整快照，baseline 固定为 null，携带文件摘要和 capabilities；不支持 delta。消费者核对支持的契约、必需依赖和摘要后激活。未来媒体体积增加时可使用文本包、媒体分片和共享对象索引；相同资源身份贯穿不同交付载体。
